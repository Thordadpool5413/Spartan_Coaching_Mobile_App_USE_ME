# Render Deployment Walkthrough — Spartan Coaching Backend

This is the **fastest path** to a live production backend. ~20 minutes total.

## Prerequisites
- A GitHub account (free)
- A Render account (free — sign up at https://render.com)
- A MongoDB Atlas account (free — sign up at https://mongodb.com/cloud/atlas) → see `/app/IOS_DEPLOYMENT.md` for the Atlas setup walkthrough
- Your Emergent LLM key (already in `/app/backend/.env` as `EMERGENT_LLM_KEY`)
- Your Resend API key (already in `/app/backend/.env` as `RESEND_API_KEY`)

## What I've prepared
- ✅ `/app/backend/Dockerfile` — production container (Python 3.11, uvicorn, 2 workers)
- ✅ `/app/render.yaml` — Render Blueprint that provisions the service end-to-end
- ✅ `/app/scripts/migrate_to_atlas.py` — one-shot script to copy your local Mongo data to Atlas
- ✅ Backend now logs a startup config summary so you can verify production wiring in Render logs

## Step 1 — Push the code to GitHub
1. In the chat input below, click the **Save to GitHub** button. This pushes `/app` to your GitHub repo.
2. After it pushes, you'll have a repo like `github.com/your-user/spartan-coaching`.

## Step 2 — Create MongoDB Atlas cluster
Follow `/app/IOS_DEPLOYMENT.md` → "MongoDB Atlas Migration" (10 steps, ~5 min). At the end you'll have a connection string like:
```
mongodb+srv://spartan_app:YOUR_PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=SpartanCoaching
```
Save it somewhere — you'll paste it into Render in Step 4.

## Step 3 — Create the Render Blueprint
1. Go to https://dashboard.render.com/blueprints
2. Click **New Blueprint Instance**
3. Connect your GitHub account and pick the `spartan-coaching` repo
4. Render auto-detects `/app/render.yaml` and shows a preview of what it'll create:
   - Web service: `spartan-coaching-api` (Docker, starter plan)
   - Region: Oregon (or whichever you set in `render.yaml`)
   - Auto-deploy on push to `main`
5. Click **Apply**

## Step 4 — Set the secret env vars in Render
After the Blueprint deploys, Render will pause asking for the four `sync: false` secrets. Set them in the Render dashboard → your service → **Environment**:

| Variable              | Value                                                                  |
|-----------------------|------------------------------------------------------------------------|
| `MONGO_URL`           | Your Atlas connection string from Step 2                               |
| `EMERGENT_LLM_KEY`    | `sk-emergent-984103441D45b2860D` (or current Emergent LLM key)         |
| `RESEND_API_KEY`      | `re_Mqvb4rvP_NAoADg62xCfqdDvwkXajJwRz` (or current Resend key)         |
| `RESEND_FROM_EMAIL`   | `onboarding@resend.dev` (use this until Resend domain is verified)     |
| `CORS_ALLOWED_ORIGINS`| `https://spartan-coaching-api.onrender.com,http://localhost:3000`      |

`ADMIN_TOKEN` is auto-generated by Render via `generateValue: true` in the blueprint.

Click **Save Changes**. Render redeploys automatically (~2 min).

## Step 5 — Verify
After redeploy completes, check your service's **Logs** tab. You should see one line like:
```
Spartan Coaching API up | Mongo=Atlas (cluster0.xxxxx.mongodb.net, OK) | CORS=2 origin(s) | Resend=configured (from onboarding@resend.dev) | Admin=rotated
```
- `Mongo=Atlas` ← Atlas connection working ✓
- `OK` ← MongoDB ping succeeded ✓
- `Resend=configured` ← Resend ready ✓
- `Admin=rotated` ← Token not default ✓

Test the live endpoint:
```bash
curl https://spartan-coaching-api.onrender.com/api/health
# {"status":"ok","timestamp":"..."}
```

## Step 6 — Migrate existing data (optional, only if you want to keep the preview's test data)
Run the migration script from your local machine (anywhere with the local Mongo running):
```bash
cd /app
pip install pymongo
python scripts/migrate_to_atlas.py \
  --source "mongodb://localhost:27017" \
  --target "mongodb+srv://spartan_app:YOUR_PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=SpartanCoaching" \
  --db spartan_coaching
```
The script upserts by `_id`, so it's safe to re-run.

## Step 7 — Point the iOS app at production
Update `/app/frontend/.env`:
```
EXPO_PUBLIC_BACKEND_URL=https://spartan-coaching-api.onrender.com
```
Then rebuild the Expo app:
```bash
cd /app/frontend
eas build --platform ios --profile production
```

## Step 8 — Custom domain (optional)
By default Render gives you `<service-name>.onrender.com`. To use a custom domain:
1. Render → your service → **Settings → Custom Domain → Add**
2. Add `api.spartanhospicecoaching.com` (or whichever subdomain you want)
3. Render shows the CNAME record you need to add to your DNS provider
4. After DNS propagates (~15 min), Render auto-provisions a TLS cert via Let's Encrypt
5. Update `EXPO_PUBLIC_BACKEND_URL` and rebuild the Expo app

## Cost on Render
- **Starter plan**: $7/month — always-on, no cold starts
- **Free plan**: $0 — sleeps after 15 min idle, 30-50s cold-start delay on next request. Fine for very low traffic.
- The `render.yaml` defaults to `starter`. Change to `free` if you want the $0 tier:
  ```yaml
  plan: free
  ```

## Troubleshooting
- **Mongo=UNREACHABLE in logs**: Atlas IP allowlist doesn't include Render. In Atlas → Security → Network Access, temporarily set `0.0.0.0/0` then narrow to Render's outbound IPs (https://docs.render.com/static-outbound-ip-addresses).
- **CORS error in browser**: Add your iOS app's web origin (and your custom domain if applicable) to `CORS_ALLOWED_ORIGINS` comma-separated.
- **Resend bounces**: Sender domain not verified yet → fall back to `onboarding@resend.dev` until DNS is set.
